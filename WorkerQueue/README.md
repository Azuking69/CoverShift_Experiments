# WorkerQueue — ワーカー・キュー・スケジューラーの最小コード（課題4）

**目的**：3人が、「ワーカー」「キュー」「スケジューラー」がそれぞれ何をする係かを、動かして理解する。
LangGraph・LINE・AWS・Claude API は**入れていない**。役割の理解だけに絞っている。

## 3つの係

| 係 | ファイル | やること | 折衷案での対応（推測を含む） |
|---|---|---|---|
| キュー | `db.sql` の `queue` テーブル | 「やる仕事」を順番に並べておく仕事リスト | SQS FIFO |
| スケジューラー | `scheduler.py` | 時刻を見張って、締切が来たら仕事リストへ足す。仕事の中身は知らない | EventBridge Scheduler |
| ワーカー | `worker.py` + `states.py` | 仕事リストから1件取り、状態遷移表で案件の状態を進める | consumer Lambda |
| 窓口 | `api.py` | 案件を作る・締切を登録する・様子を見る（仕事そのものはしない） | — |

案件の状態：`collecting`（集計中）→（締切）→ `reviewing`（検討中）→（review_done）→ `waiting_approval`（承認待ち）→（approved）→ `finished`（終了）

## 動かし方（Windows / PowerShell）

ターミナルを**4つ**開く。すべて `WorkerQueue` フォルダで実行。

```powershell
# 最初の1回だけ
pip install -r requirements.txt
docker compose up -d          # PostgreSQL（ポート5433）が起動し、テーブルが自動で作られる

# ターミナル1：窓口
uvicorn api:app --port 8000
# ターミナル2：スケジューラー
python scheduler.py
# ターミナル3：ワーカー
python worker.py
# ターミナル4：確認スクリプト
python try_it.py
```

`try_it.py` が ①基本の流れ ②順番 ③二重 の3つを確かめて、OK / NG を表示する。
ターミナル2・3のログを見ると、「誰が・いつ・何をしたか」が分かる。

## 確かめること

**自動の確認スクリプト（2つ）**

| スクリプト | 確かめること | 事前に |
|---|---|---|
| `python try_it.py` | ①基本の流れ ②順番 ③二重 ④2案件の同時処理 | ワーカーを**2つ**起動しておく（1つだと④は NG になる） |
| `python try_it_recover.py` | ⑤処理中にワーカーが落ちたら、やり直される ⑥スケジューラー停止中に過ぎた締切が、再開後に出る | **ワーカーとスケジューラーは止めておく**（スクリプトが自分で起動・停止する）。api と PostgreSQL は動かしたまま |

**ログを目で見て確かめる（手動）**
- ワーカーを2つ動かして `try_it.py` を流し、2つのターミナルの「仕事を取った」を見る。同じ仕事番号が両方に出ないこと（`FOR UPDATE SKIP LOCKED` が二重に取らない仕組み）。
- ワーカーのログに「仕事を取った」と出たらすぐ `Ctrl+C` で止める。約10秒後、別のワーカーが「止まっていたので待ちに戻した」と出してやり直す（`WORK_SECONDS`、`STUCK_SECONDS` で時間を変えられる）。

| 確認 | Claude の環境（PostgreSQL 16） | アズキの Windows |

| ①②③ | OK | OK |

| 2つのワーカーで仕事を分け合う（二重に取らない） | OK | OK（ログで確認） |
| ⑤ 落ちたらやり直し | OK（約6秒後。取り直された確認つき） | OK（取り直されたことも確認） |
